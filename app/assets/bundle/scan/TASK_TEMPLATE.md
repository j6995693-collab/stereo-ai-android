# 定时搜索任务 — 通用模板（开源版）

> 这是一个**可配置**的每日定时搜索任务。App 内置定时器 `ScanAlarm` 在每个工作日
> 09:00 自动执行一次；错过后由 `StereoService.catchUpScan` 补跑（当日一次，最多 3 次重试）。
>
> **首次使用**：把本文件复制到 App 私有目录 `files/work/scan_task.md`，填写下方
> 「任务配置」，并删除 `<!-- UNCONFIGURED -->` 这一行。也可以直接让 App 内的 AI
> 帮你创建和修改 `files/work/scan_task.md`。
>
> 自动触发的那一轮**没有人会回话**：禁止向用户提问、禁止等待确认、禁止"要不要继续"。
> 遇到门禁不通过就按规范停下，把卡在哪一道门、原始报错写进回复，并留下已完成的中间产物。
>
> 没有配置的任务不会执行（检测到 `<!-- UNCONFIGURED -->` 即跳过并通知）。

## 0.1 路径与工具（照抄，不要自己改路径）

| 名称 | 路径 |
|------|------|
| **权威库**（用户打开的那一份） | 配置区填写的 `<库.xlsx>` |
| 工具目录 | `$STEREO_BUNDLE_DIR/scan/tools/` |
| 工作目录 | `$STEREO_WORK_DIR/scan/<YYYY-MM-DD>/` |
| 原文留档 | 工作目录 `/原始源文件/<序号>_<主体简称>.html` |

`$STEREO_BUNDLE_DIR` / `$STEREO_WORK_DIR` 是环境变量，直接用，别展开成字面量。

| 工具 | 作用 | 用法 |
|------|------|------|
| `selftest.sh` | **开工自检**：工具链/库可读/目录可写/zip 写入器 | `sh $STEREO_BUNDLE_DIR/scan/tools/selftest.sh <库.xlsx>` |
| `xlsx_export.sh` | **读库** → TSV 文本（供检索去重） | `sh $STEREO_BUNDLE_DIR/scan/tools/xlsx_export.sh <库.xlsx> <输出.tsv>` |
| `xlsx_append.sh` | **入库**：把新增 TSV 追加进库并自证 | `sh $STEREO_BUNDLE_DIR/scan/tools/xlsx_append.sh <库.xlsx> <新增.tsv> <输出.xlsx> <YYYY-MM-DD>` |
| `zipw.sh` / `append.awk` / `xlsx2tsv.awk` | 上面两个脚本的零件，**不要直接调** | — |

写权限：需要在系统设置中授予「所有文件访问」（`MANAGE_EXTERNAL_STORAGE`），
才能原地写 `/sdcard/` 下的库。**若写入失败，脚本会非零退出——那就是失败，
如实报告，严禁当作成功。**

## 硬门禁（缺一不可，违反任一条 = 任务失败）

| 门 | 要求 |
|----|------|
| **门1 源文件** | 每条必须用 `web_fetch` 抓**原文页**（不是搜索结果页、不是聚合列表页）并留档；字段必须来自原文正文。抓不到正文就**丢弃该条** |
| **门2 禁臆造** | 金额、截止日期取不到就写 `N/A`，**严禁猜数字**；主体/标题/链接任一缺 → 丢弃该条。**门1+门2 的机器判据 = 第 3.5 步 `srccheck.sh`**（TSV 字段拿回原文存档里逐项找，回显 `SRCCHECK=PASS K/N`） |
| **门3 回读自证** | 入库脚本会解交付件本体、逐条回读主体，打印 `verified=K/N`。**K<N 脚本自己就会报 FAIL 并拒绝出文件** |
| **门4 交付** | `send_file` 发**更新后的库 xlsx**；正文必须带四要素（见第 6 步） |
| **门5 去重** | 入库前必须用第 4 步的 TSV 全量检索，已存在的条目不得重复入库 |
| **门6 反向比对门** | 与别的来源比对时必须**双向全量**：既查"我有他无"，也查"他有我无" |
| **门7 证据边界门** | 检索不到 ≠ 不存在。凡下"没有/搜不到"的结论，必须写明**检索范围** |

## 第0步：开工自检（★先跑这个，不通过不许开扫）

```
sh $STEREO_BUNDLE_DIR/scan/tools/selftest.sh "<库.xlsx>"
```

逐项打印 OK/FAIL，最后一行 `SELFTEST=PASS` 或 `SELFTEST=FAIL`。
**`SELFTEST=FAIL` → 立即停止，把 FAIL 的项原样报给用户，等指令。**

---

## 第1步：搜索（关键词由配置区决定）

按下表逐组搜索；组数与关键词完全由使用者定义，下面只是格式示例：

| 组 | 关键词1 | 关键词2 |
|----|---------|---------|
| 组1-`<主题组1>` | `"<关键词>" "公告" OR "通知" OR "结果"` | `"<关键词>" "<自定义同义词>"` |
| 组2-`<主题组2>` | `"<关键词>" "公告" OR "通知"` | `"<关键词>" "<自定义同义词>"` |
| 组3-`<主题组3>` | `"<关键词>" "公告" OR "结果"` | `"<关键词>" "<自定义同义词>"` |

过滤：标题或摘要必须包含配置区的**过滤词**。每组最多取前 20 条。

---

## 第2步：抓原文存证（★门1+门2，不可跳过）

对每条候选：

1. `web_fetch` 打开**原文页**。
2. 原文写入 `工作目录/原始源文件/<序号>_<主体简称>.html` 留档。
3. 只从**原文正文**取字段。**禁止**用搜索摘要凑数。
4. 抓不到原文（404/需登录/反爬）→ 该条**丢弃**（不许填"未知"硬塞）。
5. 每条额外记两列：`源文件`（原文 URL）、`原文摘录`（关键字段所在原句，一句话）。

**来源页通常含有**：主体全称、标题全称、金额、截止时间、发布方。
逐项抄下来。抄不到说明没抓到正文，回第 1 条重抓。

---

## 第3步：写今日新增 TSV

- 路径：`工作目录/新增_<YYYY-MM-DD>.tsv`
- 编码：**UTF-8 无 BOM**，**制表符分隔**（不是逗号；字段里有逗号也不要加引号）
- **14 列，顺序固定**（前 12 列入库，后 2 列留档）：

```
序号	日期	类型	地区	城市	主体	标题	金额	截止	来源	链接	关键词组	源文件	原文摘录
```

- 表头**不要写进文件**（脚本按数据行读）
- `序号` 从 1 连续编
- `日期` 格式 `YYYY-MM-DD`
- `类型` **只能取这四个值**（脚本按它分表，写错就进错表）：
  `公告` / `意向` / `结果` / `其他`
- `金额` 单位**万元**，纯数字（如 `265`、`11.95`）；取不到写 `N/A`
- `截止` 格式 `YYYY-MM-DD`；`链接` 必须是原文页 URL
- 字段内**不得含制表符**

---

## 第3.5步：原文核对（★门1+门2，机器执行，不可跳过）

```
sh $STEREO_BUNDLE_DIR/scan/tools/srccheck.sh \
   "$STEREO_WORK_DIR/scan/<date>/新增_<date>.tsv" \
   "$STEREO_WORK_DIR/scan/<date>/原始源文件"
```

逐条把 TSV 字段拿回**第2步存下的原文档案**里找，三项：

- **A 主体**全称必须出现在原文
- **B 金额**：原文必须含 `金额(万元)×10000` 元，或 `金额万元` 写法
- **C 截止日期**：原文必须含 `YYYY年M月D日` / `YYYY年MM月DD日` / `YYYY-MM-DD`

配对规则：存档文件名必须以 **`<序号补零两位>_`** 开头（序号 `1` 写成 `01_`）。

- 期望末行 `SRCCHECK=PASS K/N` 且 `K==N`（脚本 K<N 时退出码 1）
- 出 `FAIL` → 回第2步重抓原文或修正 TSV，**重跑到 PASS 才准进第4步**

---

## 第4步：去重（★门5）

1. 把库导出成文本：
   ```
   sh $STEREO_BUNDLE_DIR/scan/tools/xlsx_export.sh \
      "<库.xlsx>" \
      "$STEREO_WORK_DIR/scan/<date>/库快照.tsv"
   ```
   看输出的 `exported=N`——这就是库当前行数，记下来。
2. 对每条新增，用 `file_grep` 在 `库快照.tsv` 上查**标题**（或原文 URL）：
   命中 → 已存在，**从新增里剔除**；未命中 → 保留。
3. 记下 `exported=N`、`新增 M 条`、`去重剔除 X 条`、`实际入库 M-X 条`。

---

## 第5步：入库（★门3+门5）

```
sh $STEREO_BUNDLE_DIR/scan/tools/xlsx_append.sh \
   "<库.xlsx>" \
   "$STEREO_WORK_DIR/scan/<date>/新增_<date>.tsv" \
   "<库.xlsx>" \
   <YYYY-MM-DD>
```

（输入输出同一个路径 = 原地更新。脚本先解包、写完核对、最后才覆盖，中途失败原库不动。）

期望输出两行：

```
verified=K/N  rows: <总行数>
OK: <库.xlsx>
```

- **`K == N` 且 `总行数 == N + (M-X)`** → 通过。
- 出现 `MISS:` / `FAIL:` / 非零退出 → **入库失败，库未被改动**。回第 3 步查 TSV 格式。

---

## 第6步：交付（★门4）

```
send_file(path="<库.xlsx>")
```

正文必须含**四要素**（缺一视为未完成）：

```
<主题>（YYYY-MM-DD）
- 今日新增：M 条（去重剔除 X 条，实际入库 M-X 条）
- 入库核验：verified=N/N，库总行数 前 N + 新 M-X = 后 <总行数>
- 原文取证：抓取并留档 X 份原文（按来源类型说明）
- 库文件：<库.xlsx>（已原地更新）
```

正文只放结论与新增清单，不要把整份表贴进聊天。

---

## 第7步：收尾

- **保留** `原始源文件/`（抽检依据，不删）、`新增_<date>.tsv`、`库快照.tsv`
- 不留 `.bak*`、不留 `.xlsxwork.*` / `.work` 临时目录
- 日志追加：每组搜索条数、抓原文成功数、去重剔除数、verified 值、库总行数

---

## 反面清单（一律禁止）

1. 不抓原文就填「金额/截止日期/主体」
2. 没跑入库脚本就报"已更新 Excel"
3. 看到 `verified=K/N` 里 K<N 还说成功
4. 编造金额或截止日期（取不到一律 `N/A`）
5. 交付上一批的旧文件
6. **说"库里没有某条"却没说检索范围**
7. 用自己挑的几条当样本比对两个来源——门6 要全量双向
