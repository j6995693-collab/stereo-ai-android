## 一、坐标系错误

**错误**：使用 WGS-84 坐标直接在高德地图上绘制标记，偏移 300-400 米。

**解决**：高德地图使用 GCJ-02 坐标系。所有坐标必须通过高德 API 获取，不得手动估算。

---

## 二、Key 类型识别

**错误**：Web端 JS API Key (`<JS_KEY>`) 和 Web服务 REST API Key (`<REST_KEY>`) 混用。用 JS Key 调 REST API 全返回 `USERKEY_PLAT_NOMATCH`。

**解决**（三个值都在高德控制台「应用管理 → 我的应用」里创建，见 README）：
| Key | 用途 |
|-----|------|
| `<你的 JS API Key>` | 浏览器 JS API（地图显示），Key 类型选「Web端(JS API)」 |
| `<你的 REST API Key>` | 后端 REST API（geocoding/direction），Key 类型选「Web服务」 |
| `<你的安全密钥 securityJsCode>` | JS API 安全密钥（与 JS Key 配套） |

## 三、瓦片拼接坐标错位

**错误**：瓦片粘贴使用相对偏移，标记使用绝对偏移，当边界不是 256 的倍数时两个参考系错位。

**解决**：
1. `x1` 和 `y1` 必须对齐到瓦片边界：`x1 = (x1 // 256) * 256`
2. 瓦片粘贴用绝对坐标：`canvas.paste(tile, (tx*T - x1, ty*T - y1))`
3. 标记同样用绝对坐标：`tc(wx, wy) = (wx - x1, wy - y1)`

---

## 四、所有路线混在一张图

**错误**：多天路线存入全局字典，渲染每张图时遍历了全部路线而非仅该图路线。

**解决**：每张图只渲染属于它的路段。

---

## 五、文本标签覆盖路线

**错误**：文字+白底直接放在路线上方，遮挡地图和路线。

**解决**：路线图只保留站点标记，所有路段信息放入图外独立说明栏。

## 六、坐标来源错误（重犯 3 次）

**错误**：手动估算/猜测景点坐标。实测出现过湖泊类景点偏差 17 公里、山区 8 个 POI 全用手动坐标导致与高德 API 路线端点对不上。

**解决**：
1. 所有坐标必须通过高德 API 获取
2. **POI 标记位置必须使用 polyline 的首尾点**，不用独立查询的坐标——这样才能保证标记和路线完全对齐
3. 地理编码 API (`geocode/geo`) 对山区景点返回城市级坐标，必须改用 POI 搜索 API (`place/text`)

### 山区 POI 坐标获取策略
```
# 正确：用 POI 搜索
GET https://restapi.amap.com/v3/place/text?key=<Web服务Key>&keywords=<景区名>&city=<城市名>

# 错误：用地理编码（山区景点会返回城市中心坐标）
GET https://restapi.amap.com/v3/geocode/geo?key=<Web服务Key>&address=<景区名>
```

## 七、未验证就发送（重犯 3 次）

**错误**：渲染后直接发送，结果全灰/全白/路线没渲染。

**解决**：每次发送前必须执行：
1. Playwright 截图（用 390×844 竖屏 viewport）
2. 视觉模型复核（对截图调用 `read_image` 或你的视觉工具，确认路线可见、标记对齐）
3. 通过后再发送

---

## 八、工作流最佳实践

1. 用高德 `place/text` API 获取所有 POI 的 GCJ-02 坐标
2. 用 direction API 获取每段路线 polyline + 时长 + 距离
3. POI 标记位置 = polyline 端点（保证对齐）
4. 索道/火车等非步行段用虚线、实际道路/步行段用实线
5. 大巴段也要用步行 API 获取实际道路 polyline（大巴走的也是同样道路）
6. 地图上方 55vh + 路线列表下方（竖屏手机兼容）
7. 每条路线的 label 中注明距离、时间、费用
8. 视觉模型验证 → 发送

## 九、竖屏手机布局

**错误**：桌面端侧边栏覆盖设计，竖屏手机把地图挡死。

**解决**：
```css
body { display: flex; flex-direction: column; min-height: 100vh; }
#map { width: 100vw; height: 55vh; flex-shrink: 0; position: relative; }
.panel { flex: 1; overflow-y: auto; -webkit-overflow-scrolling: touch; }
```
地图占上半屏（55vh），路线列表在下半屏可滚动。toggle 按钮绝对定位在地图右上角。

## 十、JS 变量作用域 Bug（最致命）

**错误**：
```javascript
// IIFE 内 var 声明的变量不在 window 上
(function() {
    var day1Trails = [...];
    var day2Trails = [...];
    // ❌ window 上取不到！
    var trails = window['day' + d + 'Trails']; // undefined!
})();
```

**解决**：
```javascript
// ✓ 直接数组引用，同一个闭包作用域
var trails = [null, day1Trails, day2Trails, day3Trails, day4Trails, day5Trails][d];
```

## 十一、Python dict 不能当 tuple 解包

**错误**：从 JSON 加载的 dict 列表，用 tuple 方式解包：
```python
segments = [{"f": "A", "t": "B", "type": "walk", "d": 1}]
for f, t, stype, day in segments:  # ❌ 解包的是 key 名，不是 value
```

**解决**：
```python
for seg in segments:
    f, t, stype, day = seg["f"], seg["t"], seg["type"], seg["d"]
```

## 十五、批量请求与阶段纪律（长周期路线任务教训，先于一切效率考虑）

1. **批量请求必须带间隔**：个人 key 限 3 QPS，全速并发整批被限流。批量循环每次请求后
   `sleep 0.5`；单条被限流（`status=0`）时同样带间隔重试，**禁止退化成逐个单发**。
   实测：带间隔批量 7.9 秒完成 65 个请求；退化单发 30 秒才出 1 段。
2. **数据全量校验通过才允许进入生成阶段**：每段路线 JSON 必须 `status=1` 且
   `distance>0` 且 polyline 点数>50，33 段全部落盘并校验后才开始写 HTML。
   **禁止边拉数据边写模板**——2026-10-04 任务因数据未齐先写模板，产出语法烂尾、
   数据截断的废品。
3. **数据格式必须与渲染器匹配，嵌入前小样回验**：压缩 polyline 嵌入 HTML 前，
   必须用页面同款解码逻辑解码回验（点数一致、首点=起点、末点=终点），任一不符禁止交付。
4. **长任务先查配额、产物分段落盘**：开工前评估 token 消耗并确认模型供应商配额
   （月度限额耗尽会在任务中途直接掐断）。所有中间数据（POI、每段 JSON、meta）
   逐段落盘，保证中断后可从数据层恢复，禁止依赖"一口气跑完"。
5. **成品三道验证是交付前置条件**：体积（真实成品远大于纯模板，几十段路线应 >100KB）、
   key 注入计数（grep -c 恰为预期次数）、语法与数据回抽（JS 语法校验 + 解码抽样）。
   未过三道验证不得 send_file。

## 十六、路线规划必须先搜攻略评估（路线返工教训）

1. **规划前置门**：路线设计类任务，先搜攻略（路线走向/分段/住宿点海拔/路况/边防证/
   加油点），站表与攻略逐项比对吻合后才允许拉 API 数据。跳过直接拉数据 = 方向性错误
   全量返工（本次 33 段数据整体作废重拉）。
2. **复用旧模板必须清逻辑区残留**：替换数据区之外，全文检索旧线地名、休整日文案
   （restNotes）、硬编码天数（如 `day===33`）、meta 统计行，替换后各项计数必须归零。
3. **占位符注入断言**：注入 key 前 assert 占位符计数 ==1，注入后 assert 真值计数 ==1。
   replace 找不到目标不报错、静默跳过，页面就是空白。
4. **解码回验函数要互逆自证**：压缩 polyline 的回验解码必须带差分累计求和；先跑
   「编码→解码」小样互逆测试再用到成品。本次回验函数漏了累计，首点正确、其余全错位，
   差点误判成品数据损坏。
5. **中文文件名 adb 推送**：`run-as sh -c '含中文'` 参数会被吃掉（cp 报 Needs 1 argument）；
   拆成单条 `adb shell run-as ... cp/mv` 直传最稳。

## 十七、文件交付必须走真实手机通道（2026-10-04 三连废件教训）

**桌面端 file:// 渲染正常 ≠ 用户能打开。** 交付链路有四层，每层单独验证过才算数：

1. **MIME 层**：HttpServer `guessMime` 必须覆盖 html/audio/image/pdf 等全部交付扩展名；
   缺了返回 application/octet-stream，WebView 一律当下载，用户看到的就是「打不开」。
   验证方法：`curl -I` 看实际返回的 Content-Type。
2. **下发通道层**：HTML 交付必须走 `http://127.0.0.1:8765/api/audio?path=<urlencode绝对路径>`
   拉回，与本地文件比对 md5；只测 file:// 或只测本机渲染都算没测。
3. **原生桥层**：前端 `Android.openFile` → `fetchAndOpen` 的 ACTION_VIEW+content:// 通道
   部分 Android 系统会拒收 text/html；已修复为拦截后在 APP 内 WebView 渲染。改动涉及桥时
   必须装机后用 input tap 模拟真实点击验证。
4. **验证矩阵**：交付前四项全绿 —— ① 桌面端渲染截图 ② 视觉模型复核 ③ HTTP 拉回 md5 一致
   ④ Content-Type 正确。缺任何一项 = 没验证完，禁止 send_file。

## 十八、每日行程内容标准（2026-10-04 用户指出的旧版标准）

多日行程地图的每张日卡片，除距离/时长外**必须**包含三行内容，缺一即不合格：

1. **住宿海拔**：住宿点名称后带「(约 XXXXm)」。
2. **沿途景点与海拔**：`📍 名称 XXXXm`，用「 · 」分隔；垭口/达坂必须标海拔
   （来源：攻略多源交叉核实，高德 API 不返回海拔，禁止凭记忆编造海拔数字）。
3. **风险点**：`⚠ ` 开头的独立行（落石/高反/积雪/限速/横风等，按段具体化，
   禁止全文复用同一句）。

**地图视野标准**：
- 单日视图：`showDay` 必须 `setFitView(当日overlays)` 放大到路段，市县地名可见。
- 全部视图：`setFitView(null,true,[80,80,80,80])` 后 clamp
  `if(getZoom()<5.2)map.setZoom(5.2)`（immediately=true 同步完成再取 zoom，
  动画模式会把 setZoom 覆盖回 fit 值；clamp 需幂等，重复点击不再放大）。
- 高德 JS 2.0 的 setFitView **没有 callback 参数**，勿按 1.4 习惯传回调。

## 十九、成品交付格式与手机工具约束(2026-10-05 手机 agent 死循环事故)

1. **成品 HTML 必须多行格式交付**:数据区(routes/stops 数组)每个对象独占一行,
   禁止单行 minify。单行大文件使手机 toybox 的 tail/grep/sed 全部失效,
   手机 agent 无法编辑(实测:同一命令死循环 31 次、文件被改坏膨胀 6 倍)。
2. **多行化必须结构化重序列化**:json 解析后逐对象 dumps 再拼回,并断言解析
   结果与原对象逐项相等;禁止字符串替换 `},{`——polyline 编码字符集含
   `{` `}`,字符串替换会破坏数据。
3. **手机端工具实测基线(2026-10-05)**:sed/awk/dd/curl/tar/xxd/od 可用;
   fold/python/busybox 无;tail|grep 管道在多行文件正常、单行文件恒 0。
4. **adb 操作手机沙盒的零引号通道**:凡含 shell 语法($ ; 引号 重定向)的
   操作,一律写本地脚本后 `adb shell run-as <pkg> sh < script.sh` 执行;
   adb 会剥掉命令行引号,`sh -c '...'` 内层引号必丢,中文参数还会被吃。

## 二十一、手机 agent 能力边界与僵尸 turn(2026-10-05 实证)

1. **手机 agent 禁止构造性重写 routes/stops 数据区**:实证 9 分钟内反复重写
   整个数据区,文件体积 227KB→442KB→37KB→442KB→332KB 越写越坏(stops 丢失、
   14 个 `];`、28 个 pair)。它合并逻辑与 API 实测正确,但多对象 JSON 拼接
   超出能力圈。数据区调整由用户精确诊断后下发或修复,agent 只做:只读自检、
   send_file、回复行程表。
2. **agent turn 无文本产出超 5 分钟视为僵尸**:锁在 activeTurns,新消息被
   409 拒绝。处理:`am force-stop` + 重启 APP 清锁(文件已落盘不受影响)。
3. **执行时限**:交付动作(自检+send_file)3 分钟内完成;超时即判定路径失败,
   立即换路径,禁止反复等待。
4. 抢救技巧:坏文件中完好对象可按 `{"pair"` 分块逐个试解析抢救,
   逐对象截断到 `}` 尝试 json.loads。

## 二十二、路线必须逐段验算（用户明令，假路线事故）

**事故**:某次成品中两天往返段的 path 是
`"<lng1>,<lat1>;<lng2>,<lat2>"` 式**起终点明文坐标串**,
不是高德 direction API 的真实道路 polyline——渲染出来是直线,等于没画路线,
且未经复核就交付。

1. **path 唯一合法来源是 direction API 实际返回的压缩 polyline**。
   禁止用起终点明文坐标串(`"lng,lat;lng,lat"`)、手工坐标列表、
   或「往返段沿用去程」等方式顶替;往返段(如 A↔B)照常逐段调 API。
2. **交付前逐段格式验算(脚本化,不靠肉眼)**:每段 `path` 必须
   ① 非明文分号坐标串(含 `数字,数字;` 模式计数必须为 0);
   ② 解码后点数 >50;③ `distance>0` 且与 label 里程一致;
   ④ 段数 = 行程天数,一天不能缺。任一不过 = 整图不许交付。

   **验算用工具（手机本机可执行，不用 python）**：

   ```
   sh $STEREO_BUNDLE_DIR/tools/mapgate.sh <成品.html>
   ```

   末行 `MAPGATE=PASS` 才放行。判据、实测标定与避坑见 §二十九。
   注意 `②点数>50` 只管**道路段**：索道/小火车/步行类 2 点即正确（见 §二十九.1）。
3. **渲染验证必须覆盖首、中、末日**:截图/视觉模型不能只看第一天,
   逐日切换截图,对照 polyline 点数与画面上路线的弯曲度
   (直线/大折线 = 数据是假的)。

## 二十三、每日路线与描述分色(2026-10-05 用户明令)

1. **每天一个专属颜色**,全程统一色板顺序(如:第1天品红 `#E91E63`、
   第2天橙 `#FF9800`、第3天 `#2196F3`、第4天 `#4CAF50`、第5天 `#9C27B0`,
   循环取用),当天的 polyline 全段用当日色渲染。
2. **行程描述/日卡片标题旁必须带同色色块**,且与该日路线颜色**完全一致**:
   颜色统一放在数据区(如 `dayColors` 数组),地图渲染与文字描述都从
   同一个数组取值,禁止两处各写一套 hex 导致不一致。
3. 全部/单日视图切换后颜色保持不变;图例(如有)与实际线色同源。

## 二十四、长正文会拖死手机前端(2026-10-05 地图任务卡死实测)

**事故**:地图任务的回复正文里吐出整份 HTML(十万字量级),APP 逐字渲染,
渲染线程被占满(实测 4 秒烧掉 52 CPU 秒),界面表现为「卡死」。

1. **成品一律写文件 + `send_file` 发卡片**;聊天正文只写结论、文件路径、
   关键数字与自检结果,**禁止把整份 HTML 或大段数据粘进正文**。
2. 正文渲染上限:超过约 6 万字时前端只显示首尾摘要(中间折叠提示),
   完整内容看文件卡片。**指望靠正文把成品给用户 = 交付失败**。
3. **命令/工具打转会被自动中断**:同一条命令重复 4 次、或同一个写类工具
   用同样参数重复 6 次,引擎强制中断本轮。中断后不要「换个写法再试一遍
   同一个死路」,要停下来报告障碍。

## 二十五、往返次数才是慢的根因(实测,与桌面端差距 20 倍的原因)

**现象**:同一个地图任务,桌面端 2~3 分钟,手机上要 40~60 分钟。

**实测数据**(真机 logcat 抓的,不是推断):

| 指标 | 实测值 |
|------|--------|
| 模型请求频率 | 24 次/分钟(另一段 111 次/265 秒 = 25.1 次/分) |
| 单次上行体积 | 中位 **240 KB**,P90 317 KB,最大 333 KB |
| 单次请求耗时 | 中位 1.63 秒,P90 3.50 秒 |
| 工具调用节奏 | 45 秒内 6 次 `web_fetch`,**一次一个,零批量** |

**结论:模型不慢,慢在往返次数。** 40~60 分钟 × 24 次/分 ≈ **1000~1400 次模型往返**,
每次都要把整段上下文(中位 240 KB)重发一遍,累计上行约 **288 MB**。
每一次往返只换来一个工具调用的产出,绝大部分 wall time 花在「等下一次往返」上。

**四个放大器**:

1. **一个工具调用 = 一次往返**。规范里 12 条高德路径本该一个脚本一次跑完,
   逐个发就是 12 轮,每轮十几秒。
2. **子 Agent 各扛一份完整上下文**。4 个并行子 Agent 各自从 70~100 KB 起跑,
   同时抢同一个引擎。
3. **固定开销恒定在 ~60~110 KB**。系统提示 + 32 个工具 schema 每次都全量重发。
4. **开场白往返**:`skill_list` / `memory_list` 各调 4 次,纯属白跑
   (v3.6 起索引已直接写进 AGENTS.md 末尾,不要再调)。

**执行纪律(硬性)**:

- **一个回合发多个工具调用**:互不依赖的抓取/检索/读文件,一次全发出去。
  宁可一轮发 8 个,不要 8 轮各发 1 个。
- **多条 shell 用 `;` / `&&` 串成一条**;批量 API 写成**一个脚本一次跑完**
  (带 `sleep 0.5` 应对限流),禁止路线逐段往返。
- **子 Agent 只派真正独立且体量大的活**;琐碎活自己一次批量做完,
  派子 Agent 的开销(自包含 prompt + 独立上下文)常常大于收益。
- 中途进度报数用 `todo_write` 一次写全,不要一步一报。

**判定方法**:出现「预计 40~60 分钟」时,先看 logcat 里
`[PX] got POST` 的频率与 `len=`;若 ≥20 次/分且 len ≥200 KB,就是往返爆炸,
应立刻收敛批量,而不是继续等。

## 二十六、文件卡片"一股脑全发"的真因：前端重放历史(2026-10-06 实测)

**现象**:用户只让它做一个地图,聊天界面却冒出 5 个文件卡片,其中多是**之前任务**
留下的旧文件。"又是历史文件全发给我"。

**真因不在模型,在前端重放。** `assets/index.html` 的 `renderConvTurns(cid)`
每次渲染会话时先 `chatEl.innerHTML=''` 清空,再调 `renderFileCards(cid)`——
后者把该会话 `localStorage` 里**历史累积的所有文件卡片一次性追加到底部**。
`fileStore`(`fl_<cid>`)只增不减,按会话永久堆积。所以**每次开 App、切会话,
历史文件就会"又发一遍"**。用户看到的是重放,不是新发的。

**三处修复(全部做成机制,不是提示词)**:

1. **前端不再全量倒出**:`renderFileCards` 按 `pageLoadTs`(本次打开页面的时刻)
   把文件切成「本次新收」和「历史」两拨——新的照常显示卡片,历史的**折叠成一行**
   `📎 历史文件（N 个）· 点击展开`(`appendHistFiles()`),点开才逐个渲染。
2. **服务端强制同一轮去重**:`HttpServer.pushFile` 改为返回 `boolean`,
   同一轮内同一路径第二次推送直接丢弃(`turnSentFiles` 按 tid 记),3 秒内
   同路径重复推送也丢弃;`send_file` 拿到 `false` 就回模型
   「本轮已经发过了,已自动跳过」。**这是代码闸门,模型想重复发也发不出去。**
3. **会话串台收口**:文件事件带 `conv` 标签,`/api/files?since=&conv=` 按会话过滤,
   别的会话的文件不再落到当前会话里。

**为什么"每次都修不好"(这条最值得记)**:前面几轮的修法都是**改提示词**——
在 AGENTS.md 里写「同一产物只发一次」「禁止重发」。提示词只降低概率,不形成约束;
而真正的缺陷在前端渲染代码里,**从头到尾没被碰过**。教训:
**用户抱怨"又犯了/总改不好"时,先去代码里找机制缺陷,不要再去加一句提示词。**

**自检**:ExtTest 增至 **98 项**(新增 `pushfile-*`、`files-since-*` 共 7 条,
直接 `new HttpServer(fakeCtx, new CodexClient(fakeCtx))` 调 `pushFile` 验证去重)。

## 二十七、授权弹窗是最大的隐形耗时(2026-10-07 十小时任务实测)

**现象**:地图任务 13:00 开始,深夜还没完。日志实锤:2 小时 18 分内
模型请求只有 12 次、且**全部挤在最后 2 分钟**——其余时间引擎零活动,
全在等用户点授权弹窗。用户一点同意,跑两分钟,下一个弹窗又等几小时。

**根因(代码级)**:`McpServer` 旧版把 `edit_file` 写死进"需授权"名单,
且 `gate.approve(name, args, 0)` 的超时是 **0 = 无限等**。做地图要改几十次
文件,每次 `edit_file` 都弹窗、每次都无限期等人工点同意。以前的任务用
shell(sed)改文件不弹窗,所以没暴露;换成爱用 `edit_file` 的模型后次次中招。

**修复(2026-10-07 已做,机制级)**:
1. `edit_file` 移出授权名单——沙盒内的文件编辑不再弹窗(沙盒外路径仍弹)。
   保留弹窗的只有:日历增删改、Obsidian 读写、技能/记忆写入删除。
2. 授权等待加 **10 分钟超时**:超时自动取消,并回模型
   "不要反复重试,改用沙盒内替代方案并说明"。用户不在手机旁时任务不再死等。

**对 AI 的硬性要求**:
- **沙盒内的文件读写是自由操作**,放心用 edit_file / 写文件,不会打扰用户。
- 需要授权的操作(日历/笔记/沙盒外)一轮里最多发起一次,被拒或超时后
  **禁止换参数重试**,直接改走沙盒内方案并报告。
- 交付成品前若必须授权操作(如写入共享存储),先在正文里告诉用户
  "会弹一个授权,请在屏幕上点同意",让用户有预期。

## 二十八、坐标界门：交付前硬性数值校验(2026-10-07 定位点跑到非洲事故)

**事故**:交付的地图定位点跑到海外/非洲。成批点落在东经 17~53° 正是
**经纬度颠倒**的典型特征——中国纬度(21~53°N)被当成经度用。
同时视觉模型接口返回 Access denied,**最后一道渲染目检被跳过**,成品裸奔出门。

**交付前必须全过,缺一不可**:

1. **逐点国界校验(数值门,不可用目检替代)**:把成品里全部明文坐标和
   解码后的 polyline 点逐点检查:
   `73 ≤ 经度 ≤ 136 且 3 ≤ 纬度 ≤ 55`(中国界)。**越界点数必须 = 0**,
   并把「共检查 N 点,越界 0 点」写进交付回复。若成批越界且模式符合
   经纬互换 → 修正坐标顺序后重跑本门。

   **执行工具（手机本机可执行，不用 python）**：

   ```
   sh $STEREO_BUNDLE_DIR/tools/mapgate.sh <成品.html>
   ```

   读末行 `SUM 全量坐标对 <N>` 和 `SUM 全量越界数 <M>`——把
   「共检查 N 点,越界 M 点」原样写进交付回复。`M` 必须为 0。
   这道兜底扫描是**格式无关**的（凡 `117.xxxxx, 29.xxxxx` 形态的数对一律查界），
   所以标注点阵的多种列序、map center、任何自定义结构都跑不掉。
   压缩 polyline 用 `tools/polydecode.awk` 先解成明文再喂给它。
   > 旧版这里写「用本地 python/js 解码脚本」——手机没有 python，那等于门没做。
   > 2026-10-08 起换成上面这条 toybox 实现。
2. **地标三点反查**:至少抽 3 个已知城市核对,偏差 < 0.5°（城市坐标从高德
   geocode API 取，禁止凭记忆写）。
   (格式:经度,纬度——高德/百度一律**经度在前**,GeoJSON 也是 [lng,lat])。
3. **渲染目检不可跳过**:`read_image` 不可用(Key 失效/Access denied)时
   **禁止交付**。报告用户「视觉验证工具不可用,请在 App 设置里更新阿里百炼
   Key」,等恢复后再交付。宁可晚交,不可裸奔。

**为什么桌面端从没出过这种事**:桌面端流程的每道验证是执行者亲自跑的;
手机上是模型照规范文字执行,**规范里没写成数字判据的门,它就不做**。
所以每道验证必须写成可执行、可数数的判据,不能只写"校验数据"四个字。

## 二十九、坐标门 mapgate 工具（手机可执行，2026-10-08 建立）

**为什么有这一节**:§二十二.2 要求"逐段格式验算脚本化"、§二十八.1 要求"逐点国界校验",
但两份规范都只写"用脚本"、从没给出可执行的那个,手机上也没有——等于两门都没做。
现在补上纯 toybox 的实现。

### 用法

```
sh $STEREO_BUNDLE_DIR/tools/mapgate.sh <成品.html> [最小点数默认50]
```

`STEREO_BUNDLE_DIR` 由引擎注入 codex 进程（2026-10-17 起；
此前只注入了钩子脚本，agent 在 shell 里拿到的是空值，
`sh $STEREO_BUNDLE_DIR/tools/mapgate.sh` 会变成 `sh /tools/mapgate.sh` —— 门从调用那行就死了）。

脚本**不写任何临时文件**（2026-10-17 改）：旧版把中间结果重定向到 `/data/local/tmp`，
那是 shell 的地盘、APP 进程无写权限，在手机上必然 `FAIL: awk 执行出错`。

退出码 `0`=PASS，`1`=FAIL，`2`=用法错误。FAIL 时会逐段列出
`SEG  段号  点数  道路/非道路  判定  起终点直线距离  标签`，直接看哪段没过。
另附 `tools/polydecode.awk`（高德压缩 polyline 解码，纯算术、不依赖位运算函数）。

### 判据（全部由 12 件真成品实测标定，不是拍脑袋）

| 项 | 判 FAIL 的条件 |
|----|---------------|
| 明文分号坐标串 | 出现 `数字,数字;数字,数字` 形态（§二十二 禁止的顶替写法） |
| 越界（§二十八 国界） | 全量兜底扫描里出现经度不在 73~136 或纬度不在 3~55 的点 |
| 道路段抽稀 | 该段点数 < 最小点数 **且** 起终点直线距离 ≥ 10km |
| 空段/单点 | 道路段只解出 0~1 个点（§二十二 的"假路线"） |
| 低精度越界 | 1~3 位小数的坐标对越界（严格网要求 ≥4 位小数，这道补它的盲区） |

### 三条实测教训（改门的时候别再踩）

1. **2 点不等于假路线**。某景区「🚡 索道上行」「🚂 小火车」「🚡 索道下行」
   都是 2 点且**完全正确**——索道本来就是两点直线。
   所以索道/小火车/步行/缆车/渡轮类标签**放行**点数门；不分类型一律卡 50 点，
   会把好成品判成缺陷、诱使 agent 去"修坏"。
2. **短程腿不能只看绝对点数**。3km 的城市腿 20 个点很正常。
   要加"起终点直线距离 ≥10km"——250km 的路只有 20 多个点才是抽稀。
3. **成品数据区至少四种写法，枚举格式必然漏**。实测遇到：
   - `var day1Trails=[{path:[[lng,lat],...],label:"🚗 .."}]`（内联）
   - `const dayRoutes={D1:[[lng,lat],...]}` + `path: dayRoutes[k].map(...)`（变量）
   - `var pois=[["🏁 南大门",lng,lat,"#666",0]]`（标注点阵，名称在前）
   - `var markerData=[["景点","🏛️ 陶瓷博物馆","备注",lng,lat,"#c0504d"]]`（标注点阵，名称在后）
   所以除了按块分类，最后还有一道**格式无关的全量坐标兜底扫描**。

### 实现避坑（awk 层）

- **禁止把字符串按固定字节数向前切**（如 `substr(t, rs-60, 60)`）——会切碎多字节汉字，
  macOS one-true-awk 直接崩 `towc: multibyte conversion failure`。要从字符边界切。
- `match()` 的 `RSTART/RLENGTH` 会被内层循环覆盖，进循环前必须先存下来，
  否则 `t = substr(t, RSTART+RLENGTH)` 用错偏移会**死循环**。
- 用整份文件缓冲（`{ all = all $0 "\n" }`），因为成品里有单行 106KB 的记录。

### 已用它查出的真缺陷

**某次长距离道路段在成品里被抽稀**，两个独立成品同时中招（交叉验证）：

| 成品 | 段 | 点数 | 起终点直线距离 | 同文件其它段 |
|------|----|------|--------------|-------------|
| 样本 A | 段2「🛣️ 250.0km 6h0m」 | **28** | 138.2km | 418~3111 点 |
| 样本 B | D6「长距离道路段」 | **23** | 138.2km | 其余段均 380 点 |

（更正：初版报的 26 / 21 是切块 bug 少算 2 点后的数，真值是 **28 / 23**。）

**12 件实测样本的结果**：
- **PASS 8 件**：多种多日自驾/城市游成品
- **FAIL 2 件**：两个长距离环线成品（上表的真缺陷）
- **N/A 1 件**：只有标注点、没有折线的景点地图
- **不适用 1 件**：第三方 ECharts 导出的地图（见下"边界"）

含上面提到的 2 点索道（均 PASS）。**重跑同款路线时要盯长距离道路段的点数。**

### 边界（如实）

- 本门针对**高德/AMap 成品**（`day1Trails` / `dayRoutes` / `pois` / `markerData` 那几种形态）。
  若把**内嵌第三方压缩库**的 HTML（如 ECharts 导出的 `var e=function(t,n){return e=Object.setPrototypeOf…`
  + 内嵌省界 GeoJSON）喂进来，库代码里的 `[[`/`],[` 会被当成折线产生**假 FAIL** ——
  实测这类文件 `SUM 判定 FAIL`、`mapgate.sh` **exit 1**，但它的真数据（`SUM 全量坐标对`
  / `全量越界数`）是全好的。
  **所以：报错前先看文件是不是本门适用的 AMap 成品。** 不是的话，`SUM 判定` 与退出码都作废，
  只看 `全量坐标对` / `全量越界数` / `低精度越界数` 三行。
  实测样本：某 ECharts 导出地图全量 25263 对、越界 0，
  **数据本身没问题**，FAIL 全来自库代码里的 `[[8,8]` 这类片段。
- 严格网要求**两侧都 ≥4 位小数**（成品坐标都是 5~6 位）。1~3 位小数的坐标对由
  **低精度网**兜底判越界；界内低精度对不算失败（属精度问题，不在国界门范围）。
- 文件含**非法 UTF-8 字节**时，macOS one-true-awk 会 `towc: multibyte conversion failure`
  直接崩（rc=2），`mapgate.sh` 转成 FAIL/exit 1 —— **失败方向是安全的**（不会误放行），
  但要清楚这不是"判出来有问题"，是"没判成"。

### 改门记录（回归样本在 `/tmp/gate_test` 与 `/tmp/adv`，共 45+ 件）

**2026-10-08 第一轮**独立子 agent 复验，查出 6 个真缺陷（我逐条复核后确认成立），已全部修复：

| 编号 | 缺陷 | 修法 |
|------|------|------|
| C-1 | 切 `[[` 块时首末括号被吃掉 → 每段点数**少算 2**，50/51 点合法长段被误杀 | `block = "[" substr(after,1,e+1)` |
| C-2 | 同一根因 → 2~3 点的超长道路反被**放行**（span 因 pc<2 未算） | 加 `空段/单点` 失败分支 |
| C-3 | 无折线文件的越界坐标走 N/A 分支 → 越界被吞 → `exit 0` | 判定链先判硬违规，N/A 只在确无越界时出 |
| C-4 | 兜底正则第二字段限 `{1,2}` 位 → **经纬颠倒**的 3 位经度抓不到（正是 §二十八 事故模式）；分号正则不容空格 | 两侧都 `[0-9]{1,3}\.[0-9]{4,}`，逗号分号前后容空格 |
| C-5 | 逐点循环里反复 `substr` 整个块 → O(n²)（40k 点要 4.89s） | 改 `split(block, PP, /\],\[/)` 单趟 |
| C-6 | 第三方压缩库里的 `[[…]]` 被当成折线 → 抠出假坐标判越界，**好文件被误杀** | 折线块必须**每个元素都是坐标对**才认 |

**2026-10-08 第二轮**独立子 agent 复验（对抗性），又查出 3 个真缺陷 —— **其中 2 个是上一轮的修复自己引入的**，这是本轮最重要的教训：

| 编号 | 缺陷 | 修法 |
|------|------|------|
| C-7 | `[[` 两括号之间/坐标之间换行缩进时（多行成品，`CLAUDE_behaviors` 恰恰要求每条记录独占一行）整段**漏检** | 外层匹配、块尾探测、元素分隔三处都容忍空白 |
| C-8 | **C-6 引入的反作用**：`if (pc<2) isroute=0` 让单点/空段在查块阶段就被丢弃 → verdict 里"空段/单点"成了**死代码**，单点假路线直接漏报、`exit 0` | 改 `pc<1`，只有纯垃圾块才不算路线 |
| C-9 | 全量兜底扫描仍是 **O(n²)**（同一份 5000 坐标：95KB 0.07s，加 3MB 无坐标填充变 2.68s，40×）；C-5 只修了段内循环，文档读起来像 O(n²) 已解决 | 改 `gsub` 插标记 + `split` 单趟；并新增**低精度兜底网**堵 C-6 的越界盲区 |

第三轮同上（复验修复）又查出 1 个 —— 是 C-6/放宽元素字段带出来的假阳性：

| 编号 | 缺陷 | 修法 |
|------|------|------|
| C-10 | 纯整数数组（图表序列 `[[8,8,8],[6,6,6],[1,0,0]]`、`[[0,0],[1,1],[2,2]]`）被当折线判**越界**假 FAIL | 整块**一个小数点都没有**就不算路线（真成品经纬度必带小数） |

关键回归点：`p49`→FAIL、`p50`→PASS（边界正确）；`b3b_short5`（5 点短程）→PASS；
`r2/r3/r4`（2/3/4 点的 250km 道路）→FAIL；`t1_single`（单点假路线）→FAIL(空段/单点)；
`t3_oob_lowdec`（块非法 + 1 位小数越界）→FAIL(低精度越界)；
`t4_multiline`（多行缩进 3 点 250km）→FAIL(抽稀)；`t5_3elem`（`[lng,lat,alt]` 三元组）→FAIL(抽稀)；
`b2_reversed`（1 位小数反向）→段级抓到；
`empty.html`/`binary.bin`→`FAIL(未找到任何坐标)` 且不崩。

**教训（写进改门流程）**：修 A 类缺陷时很容易引入 B 类缺陷（C-6 → C-8、C-6 → C-10 都是这么来的）。
每次改完必须跑**完整回归套件**（不是只跑被改的那几个样本），并让**独立方**复验 ——
自己跑自己的样本永远测不出自己没想到的那一类。

## 三十、静默 undefined 事故与手机渲染自检

**事故**：手机 agent 按用户需求做「8 天自驾路线图」，交付后地图上
**没有任何站名**，只有 3+ 个 `undefined` 标签、标记互相压盖。
数据层 mapgate 实测**完全合格**：8 段真实道路、4990 点、越界 0、PASS。

**根因（两处，全部静默无报错）**：

1. 端点循环写成 `[[stop.from,start],[stop.to,end]]`，`stop` **从未声明**。
   全局找不到 `stop` 时 JS 落到浏览器内置的 `window.stop`（页面停止加载函数），
   `stop.from` = `undefined`，**不抛异常、控制台干净** → 每个站名标签渲染成 "undefined"。
   实证：`typeof stop` 返回 `"function"`。
2. 内层 `.forEach(item=>{})` 的参数 `item` **遮蔽**了外层 dayTrails 的 `item`，
   `item.day` 取到 `undefined` → 端点标记颜色 `dayColors[undefined]` 失效、按天显隐失灵。

**为什么三道自检全失效（比 bug 本身更重要）**：

1. §七/§二十二.3 要求 Playwright 截图自检——**手机没有 Playwright**，
   渲染验证在手机上结构性缺失，agent 无法看到自己画出来的画面。
2. **坐标门调用链在手机上原本就断的**（2026-10-17 已修）：
   - `STEREO_BUNDLE_DIR` 只注入钩子脚本、没注入 codex 进程 → 路径展开成 `/tools/mapgate.sh`；
   - mapgate.sh 把中间结果写 `/data/local/tmp`，APP 进程无写权限 → 必然报 awk 出错。
   修法：CodexClient 注入 `STEREO_BUNDLE_DIR`；mapgate.sh 改命令替换、不写临时文件。
3. 两处 bug 都是**静默**的：不抛错、不打日志，agent 查数据、查日志都正常，
   于是认为"已验证"就交付了。

**新增硬性要求一：成品必须内置渲染自检块**

把下面这段**原样**放进成品 `</body>` 之前，一个字都不许改、不许省略：

```html
<script>
(function(){
  var issues=[],tries=0;
  window.addEventListener("error",function(e){issues.push("JS错误:"+e.message);});
  function report(n){
    var ok=issues.length===0;
    document.title=(ok?"[自检通过] ":"[自检失败] ")+document.title.replace(/^\[自检[^\]]*\]\s*/,"");
    var bar=document.getElementById("selfcheck");
    if(!bar){bar=document.createElement("div");bar.id="selfcheck";document.body.appendChild(bar);}
    bar.style.cssText="position:fixed;left:0;right:0;bottom:0;z-index:99999;padding:7px 12px;font:12px/1.45 system-ui;color:#fff;background:"+(ok?"#1a9e55":"#d64545");
    bar.textContent=ok?("✅ 渲染自检通过：标签 "+n+" 个，无 undefined/NaN"):("❌ 渲染自检失败："+issues.slice(0,3).join("；")+"（共 "+issues.length+" 项）");
    try{fetch("/api/mapcheck",{method:"POST",headers:{"Content-Type":"application/json"},body:JSON.stringify({ok:ok,labels:n,issues:issues.slice(0,10)})});}catch(e){}
  }
  function scan(){
    tries++;
    var labels=document.querySelectorAll(".amap-text-label,.amap-marker");
    var n=0;
    for(var i=0;i<labels.length;i++){
      var t=labels[i].textContent||"";
      if(t.length===0)continue;
      n++;
      if(/undefined|NaN|null/.test(t))issues.push("标签文本异常:"+t.slice(0,30));
    }
    if(n===0&&tries<8){setTimeout(scan,1000);return;}
    if(n===0)issues.push("地图上没有任何标签");
    report(n);
  }
  setTimeout(scan,3000);
})();
</script>
```

**自检结果给谁看**——页面同时做三件事：
① 底部固定条：绿色「✅ 渲染自检通过」或红色「❌ 渲染自检失败：…」（用户一眼看到）；
② `document.title` 前缀 `[自检通过]/[自检失败]`；
③ POST 到 `http://127.0.0.1:8765/api/mapcheck`（**免鉴权**），服务端追加写入
   `files/work/mapcheck.log` —— **agent 用 `read_file` 读这个文件就能拿到渲染结果**，
   这是手机上唯一可用的运行时渲染验证通道。
